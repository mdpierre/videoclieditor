What it is

The project in plain English

This toolkit is a local video production assistant. Python does the orchestration, while external binaries do the expensive work: ffmpeg extracts audio and renders clips, whisper-cpp creates transcript data, and auto-editor makes fast silence-cut drafts. The project writes every run into a timestamped output folder, so each edit has its own transcript, ranges, clips, metadata, and final video.

Input

One media file

Point the CLI at an MP4, MOV, AIFF, CAF, or other ffmpeg-readable file.

Analysis

Audio and transcript

The toolkit extracts mono 16 kHz WAV audio and asks whisper-cpp for text, segment, and word timing data.

Edit plan

Ranges and decisions

Commands convert transcript matches, review choices, rewritten text, or manual JSON into time ranges.

Output

Rendered artifacts

The final cut lands as transcript_edit.mp4 or edited.mp4, with machine-readable metadata in run.json.

Intended workflow

How you should use it

The project now has three front doors. Use the guided agent workflow when the editor is Codex or Claude, use rewrite-edit when the final transcript already exists, and use the browser word editor when you want hands-on transcript editing.

1

Raw video into a guided editing conversation

Best when an agent needs to transcribe the video, help shape a draft, get approval, and render the final cut.

toolkit transcribe /path/to/input.mp4
# then use the guided-video-editor skill to shape the final transcript
toolkit rewrite-edit /path/to/input.mp4 --transcript-file final_draft.txt
2

Final transcript into final video

Best when you already know the finished wording. This is the cleanest CLI/API-shaped path for Codex.

toolkit rewrite-edit /path/to/input.mp4 --transcript-file final_draft.txt
toolkit rewrite-edit /path/to/input.mp4 --transcript "clean final draft"
cat final_draft.txt | toolkit rewrite-edit /path/to/input.mp4 --stdin
3

Manual transcript cleanup

Best when you want to inspect every word, delete filler, cut pauses, reorder chunks, and export by hand.

toolkit word-editor /path/to/input.mp4
toolkit word-editor /path/to/input.mp4 --model small.en
4

Fallback review sheet

Best for a simple keep/cut text pass when a browser editor is too much or an agent needs explicit segment ids.

toolkit review-sheet /path/to/input.mp4
toolkit ranges-from-review /path/to/input.mp4 --instructions "keep 3-6, 9, 12-14"
toolkit edit-from-review /path/to/input.mp4 --review review_sheet.txt

These are the available subcommands from the argparse CLI. The commands print JSON so agents can read the run directory, artifacts, and decision metadata after each run.

Uses auto-editor for silence-cut talking-head edits. Pipeline runs transcription, edit, and captions together.

Transcript matching

transcript-edit

Builds video from exact queries, fuzzy queries, or manual ranges JSON. Adds padding, clips each range, and concatenates the result.

toolkit transcript-edit input.mp4 --fuzzy-query "chapter sixteen" --fuzzy-threshold 0.55
Agent edit

rewrite-edit

Matches a final-draft transcript against word-level source timing, detects silence boundaries, builds ranges, and renders the final cut.

toolkit rewrite-edit input.mp4 --transcript-file final_draft.txt --max-silence 0.2
Browser review

word-editor

Opens the source video beside word cards so a human can remove words, chunks, fillers, and long pauses before exporting.

toolkit word-editor input.mp4
Segment review

review-sheet, review-ui, ranges-from-review

Creates a line-by-line timestamped transcript and converts keep/cut choices into a JSON ranges file.

toolkit ranges-from-review input.mp4 --instructions "cut 0-2, 5"
Review render

edit-from-review

Reads an edited review sheet, treats remaining segment lines as kept material, and renders a transcript edit.

toolkit edit-from-review input.mp4 --padding 0.2,0.5

Operating logic

How it decides where to chop

The toolkit has two kinds of chopping logic: audio silence cutting through auto-editor, and transcript-aware cutting through Python range builders. The strongest path is transcript-aware because it can preserve intended wording instead of blindly deleting quiet sections.

Core decision chain

Transcribe Extract audio and get segment or word timestamps.
Select Choose source words by final transcript, exact query, fuzzy query, review ids, or manual ranges.
Shape Add padding, snap phrase boundaries, merge adjacent ranges, and split at real silence.
Render Cut each range with ffmpeg and concatenate clips into the final MP4.

Configured defaults

Whisper modelmedium.en from models/ggml-medium.en.bin unless --model overrides it.
Audio extractionffmpeg writes mono, 16 kHz, pcm_s16le WAV audio.
Auto-editor margin0.3s,1.5s by default, or --margin PRE,POST for silence-cut rough edits.
Video codech264_videotoolbox by default, with fallback to libx264 when needed.
Transcript padding0.4,0.8 seconds by default for transcript-selected ranges.

Rewrite-edit matching

rewrite-edit tokenizes the final draft transcript and the source words, normalizes punctuation and number words, then runs a dynamic-programming matcher. It keeps source words that best represent the final transcript, supports simple merged-token cases, prefers exact full windows when possible, and can shift to a later duplicate take if the boundary score is better.

MATCH_THRESHOLD0.78 minimum similarity for one target token to one source token.
MERGE_THRESHOLD0.84 for matching two target tokens to one source word, or one target token to two source words.
MIN_ANCHOR_WORDS4 words required for stable anchor runs.
PHRASE_LOOKAROUND_WORDS6 words allowed when snapping phrase starts or ends to cleaner boundaries.

Sound and silence detection

Rewrite-edit uses ffmpeg silencedetect to identify real audio gaps before splitting otherwise adjacent kept words. This helps avoid chopping inside a sentence unless there is both silence evidence and a reasonable linguistic boundary.

noise_db-35.0dB. Audio quieter than this counts as silence for rewrite splitting.
min_duration0.2s, or the requested --max-silence when smaller.
--max-silenceDefault 0.2. Gaps longer than this may split a clip if audio silence overlaps enough.
Boundary scoreStrong punctuation helps split. Weak words like "and", "the", "to", "that", and "you" make a cut less attractive.

Transcript-edit matching

transcript-edit works at the segment level. Exact matching normalizes punctuation and number words, then checks one-, two-, and three-segment windows so phrases can cross segment boundaries. Fuzzy matching scores each window by sequence similarity, token overlap, and contains checks, then keeps the best window over the threshold.

--fuzzy-thresholdDefault 0.6. Lower values catch rougher matches but increase false positives.
merge_gapAdjacent selected ranges merge when they are within 1.0s.
Number wordsWords from zero through twenty normalize to digits, so "sixteen" can match "16".

Manual range rendering

Manual JSON bypasses transcript matching. Each range must include numeric start and end. The toolkit clips each range with ffmpeg, writes clip_ranges.json, writes a concat list, and produces transcript_edit.mp4. 

[
  { "start": 12.4, "end": 18.9, "label": "hook" },
  { "start": 44.1, "end": 58.0, "label": "cta" }
]

Setup

How to get it running

The Python package itself has no runtime dependencies. The external tools matter: ffmpeg, whisper-cpp, auto-editor, and local GGML Whisper models. 

cd /Users/michaelpierre/Documents/coding-projects/video-cli-toolkit
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .
toolkit setup
make install-global
toolkit doctor

Where files go

Modelsmodels/ggml-base.bin, ggml-small.en.bin, or ggml-medium.en.bin.
Runsoutputs/<source-stem>/<run-id>/.
Metadatarun.json captures the command path, artifacts, counts, and matching summary.
Global commandmake install-global installs a wrapper to ~/.local/bin/toolkit.

Places for improvement

What the app is missing next

The core engine is useful now. The biggest next gains are making decisions more inspectable, easier to tune, and easier for an agent to modify through structured requests.

High leverage

Inspectable edit plan before render

Add a command that outputs the proposed word matches, silences, boundary scores, and clip ranges without rendering. This would let Codex explain and adjust a cut before spending time on ffmpeg.

High leverage

Structured JSON work requests

Create a stable request schema for edits: source path, workflow, model, target transcript, padding, max silence, output style, and notes. Then Codex can accept a JSON brief and run the right command.

Next

Parameter presets

Add named presets such as tight social clip, gentle talking-head cleanup, sermon excerpt, or rough review draft. Each preset could tune padding, fuzzy threshold, max silence, and merge behavior.

Next

Visual decision report

Generate an HTML report per run with transcript words, kept/cut color coding, silence gaps, range boundaries, and links to artifacts. This would make debugging cuts much easier.

Next

Audio detection tuning

Expose silence threshold, minimum silence duration, merge gap, and weak boundary handling as CLI parameters. Right now some of the important values are constants inside Python.

Later

Batch and queue mode

Support a folder of videos, a JSONL queue of edit requests, and resumable progress. That would turn the toolkit into a small local production line.

Later

Chapter and highlight extraction

Use transcript structure to suggest hooks, calls to action, repeated takes, and clean excerpt candidates before a user writes a final transcript.

Later

Export profiles

Add output profiles for YouTube, vertical shorts, podcast clips, captions burned in, and archive quality.
